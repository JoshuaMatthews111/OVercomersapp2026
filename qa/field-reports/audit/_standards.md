# Release standard rules (iOS, Android, accessibility, blockers)

## OGN-IOS-001 [ios] (ios-hig)
**rule** No screen may render a non-scrolling vertical stack whose intrinsic content height can exceed the shortest supported viewport (iPhone SE 3 = 667pt, iPhone 13 mini = 812pt). Any full-screen column that is not inside a ScrollView/FlatList must either fit in 667pt at the default text size, or be wrapped in a ScrollView with contentContainerStyle.flexGrow: 1.
**why** This is defect O1. The onboarding/theme-picker screen's column is taller than every shipping iPhone, and because there is no scroll view the tail of the column renders past the bottom edge and is permanently unreachable. A `flex: 1` spacer cannot rescue it: RN's flexShrink default is 0, so once the spacer collapses to zero nothing else shrinks and the overflow simply leaves the screen.
**check** Static: for every file under app/, find the outermost element of the default export's returned tree; if it is not ScrollView/FlatList/SectionList/KeyboardAwareScrollView and contains >6 direct children with fixed heights/margins, fail. Concretely for app/index.tsx: assert that the element carrying styles.splashInner is a ScrollView, or that sum(child height + marginTop + marginBottom) + paddingTop + paddingBottom <= 667. Measured today at the default text size on a 393pt-wide iPhone: 99 (insets.top 59 + 40) + 172 (sealWrap 150 + mb 22) + 96 (wordmark block) + 23 (divider mt20 + h3) + 92 (tagline mt28 + 2x32) + 56 (motto mt12 + 2x22) + 194 (compact ThemeSelector incl. mt20/mb18) + 32 (dotsRow) + 63 (Get Started btn + mb12) + 58 (insets.bottom 34 + 24) = 885pt vs an 852pt screen. Device: dump the accessibility tree and assert every element's frame.maxY <= screenHeight - safeAreaInsets.bottom.
**autoCheckable** True
**violations (3)** app/index.tsx:185, app/index.tsx:206, app/index.tsx:398

## OGN-IOS-002 [both] (ios-hig)
**rule** An <Image> may only use resizeMode="cover" when the destination box aspect ratio is within 10% of the source asset's aspect ratio. Logo, crest, wordmark and any image containing text must use resizeMode="contain".
**why** This is the literal 'the ministry name / the logo is cut off' half of O1. assets/images/ogn-logo-transparent.png is 614x614 (aspect 1.00) and is drawn into a 224x124 box (aspect 1.806) with cover. Cover scales to 224x224 and centre-crops to 124 tall, discarding 50pt top and 50pt bottom = 44.6% of the crest's height. In source pixels the visible band is y 137-477 of 614. The lower arc of the circular "OVERCOMERS GLOBAL NETWORK" ring, the "EDUCATE. EQUIP. EVOLVE." ribbon and the open-book base all sit below y=477 and are cropped away. The surrounding sealWrap sets overflow: 'hidden' so nothing escapes. Every other place the same asset is used (components/AppHeader.tsx:12, app/index.tsx:234, app/(tabs)/index.tsx:131, app/(tabs)/profile.tsx:296) correctly uses contain.
**check** Static: for every <Image>/<ImageBackground> with resizeMode/contentFit "cover" and a require() source, read the asset's pixel dimensions and the resolved style's width/height; fail if |boxAspect/srcAspect - 1| > 0.10. Also hard-fail any "cover" on a filename matching /logo|seal|crest|wordmark|brand/i. app/index.tsx:188 -> styles.sealImage (app/index.tsx:411) gives box 224x124 = 1.806 vs source 1.000 = 81% deviation.
**autoCheckable** True
**violations (3)** app/index.tsx:188, app/index.tsx:411, app/(tabs)/index.tsx:163

## OGN-IOS-003 [ios] (ios-hig)
**rule** Every route screen must consume the bottom safe-area inset: either a SafeAreaView whose edges include 'bottom', or an explicit paddingBottom/marginBottom derived from useSafeAreaInsets().bottom. Hard-coded bottom padding constants are not accepted as a substitute.
**why** Nothing may sit under the home indicator. The tab bar currently hard-codes its own height and bottom padding instead of reading the inset, so it is wrong on every device whose bottom inset is not 28pt (iPhone SE = 0, iPad = 20).
**check** Static: for every file under app/ exporting a default screen component, require a match for /useSafeAreaInsets\(\)/ with a downstream `insets.bottom`, OR a <SafeAreaView> whose edges prop is absent (all edges) or contains 'bottom'. Separately, grep app/(tabs)/_layout.tsx for a literal number in tabBarStyle.height or tabBarStyle.paddingBottom and fail. Device: assert tabBar.frame.maxY == screenHeight and that the tab labels' frame.maxY <= screenHeight - safeAreaInsets.bottom.
**autoCheckable** True
**violations (3)** app/(tabs)/_layout.tsx:114, app/(tabs)/_layout.tsx:116, app/+not-found.tsx:33

## OGN-IOS-004 [both] (ios-hig)
**rule** Every Pressable / TouchableOpacity / TouchableHighlight / Button must present at least 44x44pt of touchable area: its resolved style must give height or minHeight >= 44 AND width or minWidth >= 44 (or be a full-width row), or it must carry a hitSlop that brings it to 44x44.
**why** HIG minimum hit target. 55 controls in this app are currently below 44pt with no hitSlop, including the primary 'Request Account Deletion' row (~22pt tall) and 'Forgot Password?' (~30pt).
**check** Static (a working implementation exists and produced the list below): parse each .tsx, collect the StyleSheet.create object literal into a name->properties map, then for every pressable JSX tag resolve every styles.X reference in its style prop; effective height = minHeight ?? height ?? (padding*2 | paddingVertical*2 | paddingTop+paddingBottom) + 18pt text line. Fail if effective height < 44 and the tag has no hitSlop. Device: for every element whose traits include Button, assert frame.width >= 44 && frame.height >= 44.
**autoCheckable** True

## OGN-IOS-005 [both] (ios-hig)
**rule** No absolutely-positioned child may use a negative top/right/bottom/left offset when its parent sets borderRadius or overflow: 'hidden'. Badges that sit on the edge of a rounded avatar must be siblings of the avatar inside a wrapper with extra padding.
**why** Defect S10 — the purple/gold dot on the story ring is clipped in both themes. The badge is pushed 6pt left and 3pt below its parent, and the parent is a rounded (borderRadius 43) expo-linear-gradient whose corner mask clips it.
**check** Static: for every style object containing position: 'absolute' and a negative numeric top/right/bottom/left, find every JSX element referencing it, walk up to the nearest ancestor element with a resolvable style, and fail if that ancestor's style sets borderRadius > 0 or overflow: 'hidden'. app/(tabs)/index.tsx:439 (storyBadge, left: -6, bottom: -3) is a child of app/(tabs)/index.tsx:434 (storyRing, borderRadius: 43). Device (settles which edge actually clips): inspect the story ring region and assert the badge element is present in the tree and its frame is fully inside the screen and fully rendered — if the badge is absent from the tree or its frame extends outside the ring's frame while the ring reports a corner mask, the clip is confirmed.
**autoCheckable** True
**violations (2)** app/(tabs)/index.tsx:439, app/(tabs)/index.tsx:283

## OGN-IOS-006 [both] (ios-hig)
**rule** No fixed pixel height on any container whose subtree contains a <Text>. Use minHeight instead. adjustsFontSizeToFit is not an acceptable substitute — it shrinks the user's chosen text size.
**why** Dynamic Type. RN's allowFontScaling defaults to true (and is never disabled in this repo, which is correct), so text does grow — but a container with a hard height clips it instead of growing with it.
**check** Static: for each StyleSheet entry containing /(^|[^a-zA-Z])height:\s*\d+/ (excluding minHeight/maxHeight/lineHeight), find JSX elements using it; fail if any descendant in the same JSX subtree is a <Text>. Also fail any use of adjustsFontSizeToFit. Device: set Settings > Accessibility > Display & Text Size to AX5, dump the tree, and assert no element reports truncated text (text ending in '...') and that every Text frame is inside its parent's frame.
**autoCheckable** True
**violations (10)** app/(tabs)/messages.tsx:439, app/(tabs)/messages.tsx:328, app/(tabs)/_layout.tsx:114, app/(tabs)/community.tsx:253, app/(tabs)/community.tsx:264, app/(tabs)/index.tsx:170, app/(tabs)/index.tsx:188, app/(tabs)/index.tsx:222, app/(tabs)/bible.tsx:356, app/admin.tsx:649

## OGN-IOS-009 [ios] (ios-hig)
**rule** Every Info.plist usage-description string in app.json must (a) name the specific user-visible action that triggers it and (b) correspond to at least one call site in the code that actually requires that permission. Declared-but-unused permission strings must be deleted.
**why** App Store Review 5.1.1. The app currently declares NSPhotoLibraryUsageDescription, but no code path ever requests photo-library permission: all four picker call sites use ImagePicker.launchImageLibraryAsync, which routes to PHPickerViewController on iOS 14+ and needs no permission, and grep for requestMediaLibraryPermissionsAsync returns zero hits. Keeping the string is what leaves the door open for the full-library prompt the owner's earlier run flagged.
**check** Static: build a map {NSPhotoLibraryUsageDescription -> requestMediaLibraryPermissionsAsync|MediaLibrary, NSCameraUsageDescription -> requestCameraPermissionsAsync|launchCameraAsync, NSMicrophoneUsageDescription -> launchCameraAsync with 'videos'|AudioRecorder, NSLocationWhenInUseUsageDescription -> expo-location}. For each key present in app.json ios.infoPlist, require >=1 grep hit for its trigger under app/ lib/ components/; fail otherwise. Also fail any string shorter than 40 chars or matching /^(Upload|Allow|We need|Access)/ without a named feature. Current counts: camera 1 hit (components/ChatAttachments.tsx:35), location 1 (app/maps.native.tsx), photo library 0.
**autoCheckable** True
**violations (2)** app.json:19, app.json:62

## OGN-IOS-014 [both] (ios-hig)
**rule** No dead controls. ## NO-KEY-IN-BUNDLE [both] (release-blockers)
**rule** A paid third-party API key must not be shipped inside the app binary. Bible text must be fetched through a server proxy that holds the key.
**why** DO-NOT-BREAK item 12 is satisfied on its literal terms — only EXPO_PUBLIC_* values appear in app code — but the variable EXPO_PUBLIC_BIBLE_API_KEY is a real credential for a metered third-party service, and EXPO_PUBLIC_ means it is inlined into the JS bundle (lib/publicEnv.ts:16) and additionally copied into Constants.expoConfig.extra.publicEnv by app.config.js:16, which lands in the app config inside the IPA. I verified it: the key's value occurs in the shipped dist-ios-release Hermes bundle. Anyone who downloads the app can extract it and spend the ministry's quota.
